# 006_board — status

Draft-day board (first feature per SPEC §1.2). **M2 + P3 + P6 + UI overhaul complete**; the board is now the autodraft-oriented draft helper in **two columns** (overhaul 4): left = pick strip → available-players table (the scrollable priority surface; **columns sortable by header click — the model sorts, z columns by parsed float, missing values last in both directions**); right = a scrollable rail — Recommendations → Comparison → Roster, each panel at content size (Preferred/Maximum), recs grid min-height synced to its rows so it doesn't collapse in the rail. The rail is content-width (`_sync_panel_widths` after every render — exactly its widest panel), and on a narrow window the rail scrolls horizontally (overhaul 5; the left panel's content-fixing was reverted in overhaul 6 — see below). Search dropdown bug fixed — it listed ALL players because `QSortFilterProxyModel.invalidateFilter()` is deprecated AND a no-op in Qt 6.11; the popup proxy now re-filters via `beginResetModel`/`endResetModel`, and the popup closes when the search box loses focus (event filter on the edit). Only the dropdown narrows; the pool table never filters. **Overhaul 6 (2026-10-08, second screenshot review):** (1) the popup never appeared because the `Qt.Popup` flag made `show()` steal focus from the search edit, firing the focus-out filter that hides it — flag dropped (frameless only); (2) columns were narrower than their content because `_fit_player_columns` measured with the app's default font while the theme renders IBM Plex Mono 13px medium (~8px wider) — now measured with the theme cell font; (3) the left panel is back to **stretching** (a content-fixed left panel left dead canvas on wide windows) — leftover width is empty pool-table background; the rail stays content-width; (4) stat-color cell backgrounds were being killed by the plain `QTableView::item { … }` QSS rule (any such rule makes QStyleSheetStyle drop model BackgroundRole) — rule limited to `QTableWidget::item` again, teal `:selected` rules kept; (5) the app opens maximized (`showMaximized`). The old snake grid is gone. Pool columns size to content (not uniform Stretch); the pick-name entry is a
partial-match search popup (substring, autofills on click). **Overhaul 3 (2026-10-08):**
recs "Reason" column is human-labeled via `CAT_LABELS` (FG%/FT%/3P/… not raw keys);
the offline banner is single-sourced on the board (the draft page's duplicate + its
always-empty status banner + the redundant "Draft board" title are gone);
the Roster panel no longer stretches to fill leftover height.

## Setup dialog (P1), relative panel (P3), offline mode

Unchanged from before the rewrite: SetupDialog owns team list/order/keepers/my-team and the board re-reads those stores on `refresh()`; `relative.category_tags(teams, my_team, pool_rows, excluded)` gives BUILD/COAST/PUNT (top-3 → BUILD, bottom-3 + pool can't close 25% of the gap → PUNT, flat spread → COAST); offline mode resolves teams from `effective_snapshot()` (Yahoo snapshot wins, else `settings["manual_teams"]`) with the shared `_offline` banner.

## Notes / known quirks

- `settings["rec_top_n"]` default 10 (board spin reads `service.settings().get("rec_top_n", 10)`); the setup dialog does not expose it — the rail's spin is the UI.
- The recs rail's mkt/fit column parses the scorer's reason bits (`mkt N/M → x.xx`, `fit ±x.xx z`); a reason format change requires updating the two regexes in `board.py` (`_MKT_RE` / `_FIT_RE`).
- Full `pytest tests` offscreen run dies ~72% in with a hard kill (no traceback, exit 127); every file/directory passes individually — pre-existing flakiness of the offscreen harness on long combined runs, not a test failure.
