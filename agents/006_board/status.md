## Recommender (M2.3 → P2 need-aware, B + C1)

- `ball_buddy/domain/recommend.py` — two entry points, both pure/Qt-free:
  - `recommend` (M2.3, verbatim): per-pick top-N by `rank` asc (ties by `value` desc); unranked rows sort last and carry `rank=None` → UI "—" (no invented numbers).
  - `recommend_need_aware` (P2): scores each candidate = pool `value` + `NEED_WEIGHT` × (b) **category** need + `SCARCITY_WEIGHT` × (c) C1 scarcity (weights are module constants `NEED_WEIGHT = SCARCITY_WEIGHT = 1.0`, draft-day tunable). Need is per H2H CATEGORY (9 cats via `engine.CATS`), not per position — 9-cat H2H, so the question is per category. Team/candidate projections reuse `engine.project_roster` / `engine.project_player` (same engine as matchups, so pool bias cancels). Per cat: `gap_c` = how far MY team sits below the league-median team in the better direction (`engine.DIRECTIONS` — `to` is lower-is-better), ÷ league spread (max−min across teams; 0 → 1); candidate fill `f_c` = candidate season value ÷ spread (for `to`: `1 − value/spread`, quality = low turnovers); per-cat filled = `max(0, min(g_c, f_c))` (fills clamped to [0, 1] — a higher-cat candidate who beats the league max caps at 1.0); need = sum over cats, in [0, 9]. Known limitation (documented in `recommend.py`): teams with no secured players project to all zeros (engine behaviour), which inflates every category's spread — most visibly the pct categories (0 vs ~0.48) — so the need-aware signal is diluted pre-draft, when most rosters are still empty; it recovers as picks are entered. Scarcity (C1, unchanged): max(0, median remaining pool count across positions − remaining count at the candidate's primary position); facts, not prediction. `teams` maps every team → pool rows of its SECURED players (draft picks + active keepers — all count, no starter/bench); `my_team` = `settings["my_team"]`. Efficiency: each team's secured rows projected once per call; each candidate row projected once (cached by row index). Each `Suggestion` carries a `reason` string ("value 50 · fills ft_pct & pts gaps · only 1 C left (median 2 per position)" — "no pool value" only for a blank value cell — a real 0.0 shows "value 0"; filled cats = top-2 by filled amount, engine CAT keys). **Fallback (unchanged):** no teams / blank or unknown my-team → the M2.3 ranking with a reason ("pool rank N" / "unranked (top pool order)") instead of crashing.
  - Exclusions identical in both modes: drafted picks + active keepers (caller-computed in `board.py::_excluded_names`); **opted-out keepers stay draftable/suggestable** (their pick isn't forfeited).
- Suggestion panel in `board.py` updates per current pick; alias bridging both sides. `DraftBoard._team_projections` builds the per-team secured rows from entered picks (bridged) + active keepers — already exactly the dict[team → secured pool rows] the recommender wants, no board change needed; the panel has 5 columns (Player, Pos, Value, Rank, **Reason**) and calls `recommend_need_aware` with `settings["my_team"]`.
- Tests: `tests/domain/test_recommend.py` (M2.3 regression + P2: need beats raw value on category gaps, `to` direction (low-TO fills, high-TO doesn't), uniform pts_pg-shift bias cancellation, reason names the filled CAT key, exclusions/top-n, fallbacks — canonical FIELDNAMES stat rows, realistic magnitudes); `tests/ui/test_board.py` covers the panel (M2.3 order + opted-out-keeper semantics hold — no my-team set in those tests, so the fallback path renders the same ranking).

## Setup dialog (P1)

`DraftBoard` gained a `setup_requested` Signal + a "Setup…" button in the controls block; `DraftView` opens `SetupDialog` on it and calls `refresh()` on accept — the `(teams, saved)` key in `_rebuild_board` forces a board rebuild on rename/keeper changes, which is how order/renames/keepers flow to the board. Team row order in the dialog IS the draft start order: offline `effective_snapshot` → `manual_snapshot(manual_teams)` keeps team order = list order with `draft.order=[]`, and `picks.start_order_for` falls back to `manual_draft_order` (same ordered list, both written by the dialog). Real Yahoo snapshots always win: renames are manual-mode only, and order edits only affect the fallback order when Yahoo gives no live order (the League view's up/down editor remains the live-mode fallback for that case). `settings["my_team"]` is now consumed by the P2 need-aware recommender (board suggest panel; degrades to the M2.3 fallback when blank/unknown). Lineups/waivers/trades pickers still don't read it.
