# 006_board — status

Draft-day board (first feature per SPEC §1.2). **M2 + P3 + P6 complete**; the board is now the autodraft-oriented draft helper: pick strip + available-players table + relative panel + rosters on the left, recommendations rail on the right. The old snake grid is gone.

## Files

- `ball_buddy/domain/keepers.py` — keeper model: team, player (pool-bridged via `naming`), cost round (1–13), `opted_out`. Opt-out semantics per SPEC §1.1: player back to pool eligibility, cost-round pick back to team. Validation: max 2 active keepers/team, cost round 1–13, no duplicate player.
- `ball_buddy/domain/picks.py` — pick model: round, slot (snake order), team, player; snake build (`build_snake`, even rounds reversed), `start_order_for` (live order → `manual_draft_order` fallback), `current_pick` (first unentered open pick; keeper forfeits consume overall numbers).
- `data/keepers.json`, `data/draft_picks.json` (gitignored) — atomic persistence via `io/state.py`.
- `ball_buddy/ui/views/setup_dialog.py` — Setup dialog (P1): teams & draft-order table, keepers table (opt-out, resolved/UNMATCHED status), Save/Cancel. Writes `settings["manual_teams"]` / `["manual_draft_order"]` / `["my_team"]` + keepers.json — the stores the board reads.
- `ball_buddy/ui/views/draft.py` — draft page: offline banner, over-cap (2/team) keepers.json drop alert, embedded board; `refresh()` re-loads snapshot + keepers.json, `_rebuild_board` re-creates the board when `(teams, saved)` changes and re-connects `setup_requested`.
- `ball_buddy/ui/views/board.py` — **the draft helper (rewritten in place; module + `DraftBoard` name kept so `draft.py:139` import + `_rebuild_board` survive).**
  - **Strip:** `"R{r} · pick {n}/{total} · {team}"` label (draft complete when `current_pick` is None), name entry with `QCompleter` over pool-minus-excluded, **Commit** (Enter also), **Log selected** (logs the players-table selection — one code path for logging, no per-row buttons), **Undo last**, **Setup…**. Commit/undo persist via `picks_mod.save` + re-render; corrupt `draft_picks.json` falls back to the last loaded picks with a banner.
  - **Available players:** `PlayerTableModel` (`QAbstractTableModel`) + `QTableView` — model-based because the pool runs to hundreds of rows. Columns: Name/Pos/Value/Rank + one column per engine cat with the pool's signed z (canonical column via `scorer.CAT_Z_COLUMN`), stat-colored `BackgroundRole` from `theme.stat_color` (transparent in the neutral band; `to` passes `lower_is_better=True` — the pool's raw `z_to` is not sign-corrected). Blank pool z cells render empty (no faux `+0.0`); the same applies to the roster panel's stat cells. POS filter = `QComboBox` (All + present primary positions) applied **in the model** (`set_pos_filter` → model reset). Double-click = log selected row.
  - **Relative panel (P3):** 9 columns × 4 rows (`My team / League median / Gap / Tag`) from `relative.category_tags`. Gap row cells are stat-colored: normalized `-gap/spread` (positive = ahead = green, behind = red), neutral band uncolored. Hidden when no `my_team` / no teams / `category_tags` returns `None`.
  - **Roster panel:** team `QComboBox` (default `settings["my_team"]`, else first team; selection preserved across re-renders), amber "NOT MY TEAM" flag (warning tokens, inline stylesheet) when selection ≠ my-team. Rows: keepers (label `keeper R{r}`, ` (opted out)` suffix) then picks in round order (`pick R{r}`); bridged pool row supplies pos/value/z cells with the same stat-coloring as the players table (roster reads the pool directly; `_team_projections` stays recommender/relative-only).
  - **Recommendations rail (right, `#panel`):** title + **Top-N spin (1–20, default 10)** persisted to `settings["rec_top_n"]` on change (setup_dialog pattern; a board built on the same service reads it back; spin change re-renders the rail live). 5-column grid: #, Player, **Tag chip** (REACH = info tokens, VALUE = success tokens, ` · GAP` + warning tokens when `suggestion.gap`), **mkt/fit** (`"mkt X% / fit Yz"` parsed from the scorer's reason bits via regex — the reason string stays the single source of the split numbers), **Reason** (verbatim). Ordering is `recommend_need_aware` (P6 scorer path when my-team is known, M2.3 fallback otherwise — fallback rows show `—` tag/mkfit). Empty pool or draft complete → grid clears.

- `ball_buddy/ui/theme.py` — **`stat_color(z, lower_is_better=False, theme="light") -> QColor`** (global helper, documented): signed z → percentile via `math.erf` CDF; **45–55th percentile band → `Qt.transparent`** (uncolored — works on cream AND dark; autodraft's bg-color trick does not); outside the band, lerp pale-tint → endpoint over the 45 remaining percentile points. Endpoints are hardcoded per theme in `_STAT_ENDPOINTS` (doc'd): light `#145900`/`#500000` with pale tints toward white; dark the lighter `#4ade80`-class `#4ade80`/`#f87171` (THEMES success/danger themselves would be unreadable as cell text). ## Setup dialog (P1), relative panel (P3), offline mode

Unchanged from before the rewrite: SetupDialog owns team list/order/keepers/my-team and the board re-reads those stores on `refresh()`; `relative.category_tags(teams, my_team, pool_rows, excluded)` gives BUILD/COAST/PUNT (top-3 → BUILD, bottom-3 + pool can't close 25% of the gap → PUNT, flat spread → COAST); offline mode resolves teams from `effective_snapshot()` (Yahoo snapshot wins, else `settings["manual_teams"]`) with the shared `_offline` banner.

## Notes / known quirks

- `settings["rec_top_n"]` default 10 (board spin reads `service.settings().get("rec_top_n", 10)`); the setup dialog does not expose it — the rail's spin is the UI.
- The recs rail's mkt/fit column parses the scorer's reason bits (`mkt N/M → x.xx`, `fit ±x.xx z`); a reason format change requires updating the two regexes in `board.py` (`_MKT_RE` / `_FIT_RE`).
- Full `pytest tests` offscreen run dies ~72% in with a hard kill (no traceback, exit 127); every file/directory passes individually — pre-existing flakiness of the offscreen harness on long combined runs, not a test failure.
