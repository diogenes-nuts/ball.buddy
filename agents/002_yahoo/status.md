# 002_yahoo — status

Yahoo adapter: the only module that talks to the Yahoo API. Real wrapper is **`yfpy==17.0.0`** (SPEC's `yffapi`/`pyffl` don't exist on PyPI — verified).

## Files

- `ball_buddy/io/yahoo/oauth.py` — in-app OAuth 2.0 (added for the windowed exe: yfpy's `yahoo_oauth` sign-in ends in a console `input()` and cannot run in a `--windowed` build). One-shot local **https** loopback callback server on `https://localhost:8480/callback` — Yahoo's developer console rejects plain-http callback URIs, so `ensure_loopback_cert(data_dir)` generates a one-time self-signed cert for `localhost` (`cryptography` dep, 10-year, stored in `data/`) and the browser shows one expected "connection isn't private" warning page; falls back to plain http (paste-only) if the cert cannot be created. `LocalCallbackServer` strictly one-shot (the first redirect decides the outcome; later code-less hits — a tab reload or bare-URL navigation — get a 400 "already captured" page and never clobber a captured code), pollable with `wait(timeout=0)`, `new_pkce()` (S256 verifier/challenge), `begin_sign_in(data_dir, key, secret="")` (opens browser + authorize URL with `client_id` — Yahoo requires it as a query param — and a PKCE challenge when no secret is set), `complete_exchange()` / `exchange_code()` / `refresh_access_token()` (token endpoint; confidential clients: Basic-auth key:secret, **public clients — no secret — send `client_id` + `code_verifier` in the body, no auth header); `extract_guid` (JWT `sub` claim; `new_token_dict` treats it as best-effort — the GUID is bookkeeping only, yfpy requires the key but never sends the value, so a non-JWT token falls back to the payload `guid` field or `""` instead of failing sign-in), `parse_paste` (manual fallback: full redirect URL / query string / bare code).
- `ball_buddy/io/yahoo/client.py` — facade over yfpy `YahooFantasySportsQuery`; `_call` maps failures: yfpy `sys.exit` → `LoginRequiredError`, token/oauth words → `LoginRequiredError` ("token is dead — sign in again"), **403 "application is not authorized" → distinct `YahooError` app-ban message** (it's an app-level authorization problem, not a dead token — re-signing in can't fix it; surfaces as a "Sync failed:" banner); `from_tokens(settings, tokens)` builds it (consumer key from the token dict with settings fallback, key required, **secret optional** — public clients have none; persist requires every token field except `consumer_secret` and `guid` (both legitimately empty for public/non-JWT tokens); requires a logged-in token — `LoginRequiredError` otherwise; stamps `token_time` fresh so yahoo_oauth's internal 3540s validity window passes and its console-based refresh never runs; yfpy `sys.exit(1)`s on an empty `consumer_secret`, so an empty real secret is passed as the placeholder `"public"` into yfpy only — the client itself keeps the real empty value, so `persist_token` stores `""` and later token requests correctly go through the public-client path); lazy instance; `LoginRequiredError` / `YahooError`.
- `ball_buddy/io/yahoo/snapshot.py` — maps yfpy models to small explicit dict shapes → stable `snapshot.json` (league, teams, draft order, schedule).
- `ball_buddy/io/state.py` — salvaged atomic-write JSON (from autodraft `state.py`): tmp+rename, no torn files.
- `ball_buddy/services/sync.py` — `SyncService(data_dir)`: settings (league_id, consumer key in `data/settings.json`), `sync()` → snapshot, login-required / offline fallback to last snapshot; manual team-order support; token lifecycle: fresh (< ~54 min) tokens used as-is, stale tokens refreshed via `oauth.refresh_access_token` (passes the settings secret, possibly empty) and re-persisted; `sign_in_ready()` (key required, secret optional — `""` for public clients) / `save_sign_in()` for the dialog; `reset_all_data()` wipes the whole data dir (M7.2 — all loaders treat missing files as empty defaults, so the app keeps running until restart).
- Settings UI: `SettingsDialog` + button in `ball_buddy/ui/views/league.py`; **"Sync now"** also runs `SyncService.run` off-thread with the same store-first/`thread.finished` pattern (`_store_sync_result` + `_on_sync_thread_done` — `thread.wait()` inside a queued finished slot deadlocks the main loop and hard-crashes the windowed exe; regression test `test_sync_now_thread_round_trip`); **sign-in dialog**: `SignInDialog` + `_SignInExchangeWorker` (off-thread exchange; result stored on the main thread, UI updated on `QThread.finished` — waiting inside the signal slot deadlocks on the queued `quit`). `data/` is gitignored (tokens).

## Behavior

- Yahoo token format: the token endpoint (public client) mints a real ~1KB **JWT** access token on exchange and on refresh (1h validity, `expires_in 3600`); `extract_guid` reads its `sub` when present, else the dict stores `""` (best-effort). **Known upstream wall (yfpy issue #84, since ~2026-07-22): Yahoo 403s the whole fantasy API for legacy developer apps ("application is not authorized") regardless of valid tokens/scope/PKCE — new apps no longer get a Fantasy Sports permission; access now goes through a gated application program at sports.yahoo.com/developer.** The app degrades to its offline snapshot + manual pool import until that clears.
- Login: League → **Sign in to Yahoo** → `SignInDialog`: local callback server captures the redirect automatically; **Enter code manually** falls back to pasting the redirect URL (or bare code) if the callback URI isn't registered in the Yahoo developer app (one-time setup, surfaced in the dialog text). Headless-safe: no browser → clear `LoginRequiredError` → UI shows last snapshot + stale notice.
- All non-adapter code is yfpy-free and testable with fixtures (`tests/fixtures/`).
