## Findings (code-grounded)
- PlayerTableModel.data() per cell: _parse_z (split+float) + stat_color
  (math.erf + QColor lerp, uncached, 3x/cell per Display/Background/Font
  roles) — measured cheap overall. (told no)
- apply_theme = build_qss (string) + app.setStyleSheet (sync, ALL
  widgets) + save_settings (trivial). (told no)
- Only ONE QAbstractTableModel (board.py:66); other views QTableWidget+
  setItem. (told no)
- Rust answer (forming, told no): NOT a language issue — PySide6 is
  native C++; measured Python overhead negligible (505k data() calls/s).
  Costs are Qt re-polish + per-cell brush paint strategy. Fixable in
  place: theme = avoid whole-app QSS re-polish (scope to visible view,
  or precompute and apply smarter); scroll = cache per-row QBrush
  (rebuild on refresh/theme change) + possibly uniform row heights;
  measure real-screen paint if scroll still lags after brush caching.
  Rewrite cost >> these fixes.
